# 10 给留学顾问的导出（P5 最小版本）

> 状态：draft v0.5（2026-11-23：学费按学期分列时取秋季；学生版“数据整理中”）。v0.4（2026-11-23：显示方向；“待取得”）。v0.3（2026-11-22：顾问版与学生版、学校英文简称必填、学位缩写、时长合并为区间、学费估算总额、学年写法、默认包含抽检项目、“页面未写明”、自动筛选）。v0.2（2026-11-20，负责人看过第一份导出后：方向、学校简称、学位名称、排序、“见其他页面”的链接、与标准答案集不一致时标待核实）。v0.1（2026-11-20）。目的是拿给留学顾问看，验证需求；形式以后可能改。依据：02 v0.7、05、08 v0.8。

## 1. 命令与范围

- `gradprog export [--audience advisor|student] [--out <路径>] [--on <YYYY-MM-DD>]` → 一个 xlsx，默认写到 `data/exports/<audience>_<日期>.xlsx`（不进 git）。`advisor`（默认）是顾问版，即本文 §2–§7；`student` 是学生版（§8）。两个版本用同一份数据。
- 只读当前结果（`data/extraction/derived/current.csv`）、登记表、快照索引和变化记录，**不调用 API，不放任何页面原文**，只放链接。
- 项目：登记表中 `status = selected`、且至少有一个未停用页面的项目。
- 包含全部项目，含独立抽检集（09 §6）的项目（2026-11-22，负责人决定）。
- `--on`：判断“已过期”所用的日期，默认当天（UTC）。

## 2. 说明表

导出日期；页面检查日期的范围；免责声明“数据整理自各校官网，申请前请以官网最新信息为准。”；各标记的含义：
- **待核实**：这个值进了审核队列（08 §10，另加 §5 的规则），或有多个不同的值，还没有人工核对。单元格标黄，原因写在“待核实说明”列。
- **已过期**：截止日期早于导出日期。标灰，排在最后。
- 只招秋季的项目，学期按日期推算。
- **页面未写明**：收录的官网页面没有写这一项，不代表没有这项要求，也不代表答案是“否”。
- **待取得**：这个项目还有收录的页面没有取得过（多是等待人工保存的页面），没有值的项暂时不能判断是否写明（2026-11-23）。
- 见其他页面、时长区间、学费估算总额的含义。

所有表开启自动筛选。

## 3. 项目总表

每个项目一行，中文表头：方向、学校简称、学校、项目、学位、STEM、时长、托福（旧制）、托福（新制）、雅思、GRE、GMAT、申请费、学费、学费估算总额、入学季、官网链接、最后检查日期、待核实说明。

### 3.1 取值写法

| 列 | 写法 |
|---|---|
| 方向 | 登记表的显示方向：`display_group` 不为空时用它，否则用 `cip_group`（06 §2.8，2026-11-23）：ds 数据科学、analytics 商业分析、stats 统计、econ 经济、mgmt_sci 管理科学；扩展批次（2026-11-22）：cs 计算机科学、ece 电子与计算机工程、fin_eng 金融工程、ieor 工业工程与运筹、info_sys 信息系统、biostat 生物统计 |
| 学校简称 | 登记表 `institution_short`；有 `institution_name_zh` 时写“简称 / 中文名”（06 §3.1） |
| 学位 | 登记表 `degree_label`；没有时，`degree_type = other` 从项目名取缩写（MQE、MQM），其他写 `degree_type` 大写（MS、MA） |
| STEM | `stem_claim_on_page`：yes →“是（页面声称）”，no →“否（页面写明）”；页面写了 CIP 时加“，CIP 30.7001” |
| 时长 | 合并为一个区间：选中的最短值中最小的，到选中的最长值中最大的（例如 BU 有 9、12、16 个月三个方向 →“9–16 个月”）；相同时写“12 个月”。不同方向的长度不同不算矛盾：冲突类原因和“多个不同的值”不标待核实，其他原因照常 |
| 托福、雅思 | 数字原样；有条件录取区间不放 |
| GRE、GMAT | required 必需、optional 可选、not_required 不要求、not_accepted 不接受、conditional_waiver 可申请豁免 |
| 申请费 | “$125”；0 →“免申请费” |
| 学费 | “$1,288 / 学分（2026-2027）”，学年统一写成 2026-2027（2026-27、2026/27、2026–2027 都改为这个格式）；口径：每学分、每学期、每年、项目总额；没写口径时只写金额；含杂费时加“，含杂费”；多条学费用“；”分隔 |
| 学费估算总额 | 选中的学费各自的 `tuition_program_total_usd_est`（08 §3.1）；按学分算的写“$55,008（$1,528 × 36 学分）”；同一金额只写一次，页面写明的总额优先；都算不出时留空，说明表注明这是估算。学费标待核实时它也标 |
| 入学季 | 登记表 `intake_terms`：秋季、春季、夏季 |
| 官网链接 | 项目首页（`page_type = program_home`）的网址 |
| 最后检查日期 | 该项目各页面最近一次成功取得的日期中最早的一个 |

按方向（上表顺序）、学校简称、项目名排序。

没有值时（顾问版）：`referenced_elsewhere` →“见其他页面：<链接文字或网址>”，单元格链接到该页面：页面写的是网址时直接用；写的是链接文字时，在给出这句话的页面的原始快照中找文字相同或相互包含的链接，只有一个时用它，找不到或不唯一时链接到给出这句话的页面；`mentioned_without_value` →“提到但未给值”；`not_mentioned` →“页面未写明”；`extraction_failed` →“待核实（抽取失败）”；`page_unavailable` →“待核实（页面无法访问）”。

**待取得**（2026-11-23）：项目的收录页面中有从未成功取得过的（“最后检查日期”为“从未”，多是等待人工保存的页面）时，该项目状态为 `not_mentioned` 的单元格（包括没有任何抽取结果的单元格）写“待取得”，不标待核实、不写说明。其他状态和有值的单元格照常。页面取得并补抽后，按正常规则显示。

每个有值的单元格链接到给出该值的页面。

### 3.2 多个值时怎么选

按“项目 × 字段”处理：
1. 只看 `found` 的值，去掉带 `cross_program_contamination` 的。
2. 冲突处理给出了默认建议（`suggested_observation_id`，08 §8.1），只用建议的那条。
3. 否则只用层级最具体的页面：项目页 > 系页 > 研究生院页。
4. 剩下的不同值都列出，用“ / ”分隔，并标待核实（原因“页面上有多个不同的值”）。学费不按这一条判断：不同口径的学费可以并存，是否矛盾由 08 §8 判断。
   - **学费按学期分列时取秋季**（2026-11-23）：学费的 `tuition_year` 是单个学期（如 Fall 2026、Spring 2027、Summer 2027，Autumn 算秋季），且其中有秋季的，只用秋季的那些条，因为学生秋季入学。学年写法（2026-2027、Fall 2026 - Summer 2027）和没写学年的照常保留。没有秋季时照常全部列出。学费估算总额用同样的选择。
5. 没有 `found` 时，状态取 `found` > `referenced_elsewhere` > `mentioned_without_value` > `not_mentioned` > `extraction_failed` > `page_unavailable` 中最靠前的。

### 3.3 待核实

选中的值（或选中的无值状态）所在的行有审核原因（08 §10，按 §5 调整后），或 §3.2 第 4 条剩下多个值，就在值后加“（待核实）”，单元格标黄，原因用中文写进“待核实说明”，例如“托福（旧制）：同一页面的数值互相矛盾”。

## 4. 截止日期表

每行一个日期：学校简称、学校、项目、学期、轮次（页面原文）、类型、适用对象、日期、状态、待核实说明、来源链接。

- 来源：`found` 的截止日期，去掉带 `cross_program_contamination` 的。
- 类型：application 申请截止、deposit 押金、decision_release 录取结果、international_docs 签证材料、other 其他。适用对象：all 全部、international 国际学生、domestic 美国本土、funding_consideration 奖助评选。
- 只写滚动录取、没有日期的：日期写“滚动录取”。学期为 `term_unknown` 时写“未确定”。
- 同一项目、日期、类型、适用对象出现在多个页面时只留一行：层级最具体的页面；层级相同时优先写明了学期的那一条。
- 状态：日期早于 `--on` →“已过期”（标灰，排在最后）；否则有审核原因 →“待核实”（标黄）；否则留空。排序：未过期的按学校简称、学期（同一年按春、夏、秋）、日期，已过期的随后，顺序相同；学期未确定的排在该校最后。

## 5. 导出层的审核调整（2026-11-20）

- 只招秋季的项目（`intake_terms = fall`），`term_inferred`（08 §10 第 2 条）不算待核实。
- 截止日期所属学期的季节不在该项目 `intake_terms` 里时，标待核实，原因“该学期不在项目入学季内”（例如 UW MSDS 取消春季入学后，系页仍列春季截止日期）。
- 标准答案集（09）中的项目：导出的值与标准答案不一致时，标待核实，原因“抽取结果与人工标注不一致”。项目总表比较选中的值（或无值状态）与该字段的标准答案；截止日期表中，“日期 + 类型”不在标准答案中的行标出。抽取所用快照的正文与标准答案的快照不同的页面不比较，因为页面可能已经更新。
- 这三条只影响导出，不改 08 的审核队列。

## 8. 学生版（2026-11-22）

给申请者看的精简版，和顾问版用同一份数据、同一套取值与待核实判断（§3–§5），只改呈现。不出现任何内部标记：没有审核原因、待核实说明、标色、证据、快照编号。所有表开启自动筛选。

### 8.1 项目总表

10 列：方向、学校（简称，有中文名时“简称 / 中文名”）、项目、STEM、时长、托福、雅思、GRE、学费估算总额、下一个申请截止日期。项目名链接到项目首页。排序同顾问版。

| 列 | 写法 |
|---|---|
| STEM | 是 / 否（不写 CIP） |
| 托福 | 旧制和新制合成一列：都有 →“100（新制 5.0）”；只有旧制 →“100”；只有新制 →“新制 4.5” |
| 时长、雅思、GRE | 同顾问版 |
| 学费估算总额 | 有估算时写金额（不写算法）；没有估算但有学费时写“<学费>，总额请查看官网”（例如“$1,288 / 学分，总额请查看官网”） |
| 下一个申请截止日期 | 导出日期当天及以后、类型为申请截止、适用对象为全部或国际学生的日期中最早的一个，写“2027-01-07（Round 3）”（没有轮次名时只写日期）；只有不带日期的滚动录取时写“滚动录取” |

- **不确定的值**（顾问版标待核实的）：保留值，后面加“（请以官网为准）”，链接到给出该值的页面。托福两列中任一列不确定，合并后的值就加。下一个申请截止日期取自的那一行在顾问版标待核实时同样加。
- **数据整理中**（2026-11-23）：顾问版写“待取得”的单元格（包括顾问版写“待取得，CIP …”的 STEM 列）只写“数据整理中”，不附带其他内容，链接到项目首页；待取得的项目没有可取的下一个申请截止日期时也写“数据整理中”。名词解释加一条。
- **没有值**（页面未写明、见其他页面、提到但未给值、抽取失败、页面无法访问，以及没有可取的下一个申请截止日期）：统一写“官网未写明，请查看官网”。有指向的页面（见其他页面）时链接到该页面，否则链接到项目首页。

### 8.2 截止日期表

列：学校、项目、学期、轮次、类型、日期、来源链接。

- 只放未过期的申请截止日期（`deadline_type = application`，日期不早于导出日期）；押金、面试通知、录取结果、签证材料和其他类型都不放。
- 适用对象：只适用于美国本土（`domestic`）的不放；全部、国际学生的类型写“申请截止”；奖助评选（`funding_consideration`）的类型写“奖学金优先截止”。
- 不带日期的滚动录取写“滚动录取”，排在最后；其余按日期、学校排序。
- 不确定的日期加“（请以官网为准）”。

### 8.3 最近变化

变化记录（§6）新增 `fields` 列：这条变化涉及的内容，`deadline`（截止日期）、`scores`（分数要求）、`gre`（GRE / GMAT 政策）、`intake`（入学季）、`tuition`（学费）中的一个或多个，分号分隔；都不涉及时为空。学生版只放 `fields` 非空的变化，列：日期、学校、项目、变化、页面链接。

### 8.4 名词解释

替代说明表：STEM 与 OPT（STEM 认定的项目，毕业后 OPT 可在 12 个月之外再延长 24 个月，最长 3 年；以学校国际学生办公室的说明为准）；托福新旧分制（2026 年 1 月 21 日起托福采用 1–6 分的新分制，此前为 0–120 分）；轮次；滚动录取；学费估算总额的含义；“请以官网为准”和“官网未写明，请查看官网”的含义；免责声明。
